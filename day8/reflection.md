# Day 8 Reflection

The most difficult concept in this course was designing a system that can handle many users at the same time without losing data or creating errors. At first, it was not easy to understand how caching, load balancing, databases and transactions work together. I overcame this by breaking the system into smaller components and thinking about what happens when many users make requests at the same time. Working on the TicketHub assignment helped me understand why database transactions and constraints are important, especially when two customers try to buy the same seat.

Based on the feedback I received on my capstone, I would improve the system design by making the architecture and the reasons behind each technology choice clearer. I would also improve how I explain the expected traffic and how the system handles failures. This would make the design easier to understand and show that the decisions are based on actual requirements rather than just choosing technologies.

Next, I want to learn more about database optimisation, caching with Redis, and cloud deployment. I would also like to practise load testing using tools such as k6 to see how an application performs when many users access it at once. These skills will help me design systems that are more reliable, secure and scalable.
